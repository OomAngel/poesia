## Q1. Does Claude/Claude Code generate images natively, and what does Claude Code support for viewing images, MCP, plugins and skills?

### Takeaway
No. Anthropic's vision docs (fetched 2026-10-07) say Claude only understands images and cannot generate or edit them. Claude Code can *view* image files through its Read tool, so it can judge results. Image generation has to come from an external model, reached through MCP (stdio, HTTP or WebSocket), a Bash-invoked CLI, or a skill/plugin that wraps either one.

### Cited Findings
- From the vision FAQ: "Can Claude generate or edit images? No, Claude is an image understanding model only. It can interpret and analyze images, but it cannot generate, produce, edit, manipulate, or create images." (fetched 2026-10-07) — [Claude Docs: Vision](https://platform.claude.com/docs/en/build-with-claude/vision)
- Vision limits: up to 600 images per API request (100 for 200k-context models, 20 per turn on claude.ai), at most 8000x8000 px, 10 MB per image via the API. Requests with more than 20 images get a stricter per-image limit (keep each side ≤2000 px). Claude 4.7 and later models use a "high-resolution" tier (max long edge 2576 px, 4784 visual tokens); other models cap at 1568 px. — [Claude Docs: Vision](https://platform.claude.com/docs/en/build-with-claude/vision)
- Documented vision limitations include "Spatial reasoning: Claude's coordinate and localization outputs are approximate" and "Accuracy: Claude might hallucinate or make mistakes when interpreting low-quality, rotated, or very small images under 200 pixels". The docs also say "Do not use Claude for tasks requiring perfect precision or sensitive image analysis without human oversight." — [Claude Docs: Vision](https://platform.claude.com/docs/en/build-with-claude/vision)
- For comparisons, the docs recommend labelling each image ("Image 1:", "Image 2:") in multi-image requests. They also say Claude "works best when images come before text". — [Claude Docs: Vision](https://platform.claude.com/docs/en/build-with-claude/vision)
- Claude Code Read tool: "PNG, JPG, and other image formats are returned as visual content that Claude can see… Claude Code resizes and recompresses large images… An image that is still larger than 500KB after that resize is re-encoded as a JPEG at reduced quality… If Claude misses fine pixel-level detail in a large image, ask it to crop the region of interest first." — [Claude Code tools reference](https://code.claude.com/docs/en/tools-reference)
- MCP transports in Claude Code: HTTP is recommended (the JSON alias `streamable-http` also works). SSE is deprecated; from v2.1.265, `--transport http` falls back to SSE automatically. stdio runs a local process. WebSocket (`ws`) can only be configured through JSON. Scopes are local (`~/.claude.json`), project (`.mcp.json`, kept in version control) and user. — [Claude Code MCP docs](https://code.claude.com/docs/en/mcp)
- MCP output limits: a warning above 10,000 tokens and a default cap of 25,000 tokens (`MAX_MCP_OUTPUT_TOKENS`). "Tools that return image data are still subject to `MAX_MCP_OUTPUT_TOKENS`". Only text-only results that go over the limit are spilled to a file. — [Claude Code MCP docs](https://code.claude.com/docs/en/mcp)
- MCP security: "Verify you trust each server before connecting it. Servers that fetch external content can expose you to prompt injection risk." Project `.mcp.json` servers require approval in interactive sessions but "load without asking" in `-p`/SDK runs. A cloned repo cannot approve its own servers. Credential variables such as `ANTHROPIC_API_KEY` resolve to empty strings inside remote `url`/`headers`. — [Claude Code MCP docs](https://code.claude.com/docs/en/mcp)
- Skills: "a skill's body loads only when it's used". Skills can bundle scripts ("executed, not loaded") referenced via `${CLAUDE_SKILL_DIR}`. `allowed-tools` pre-approves e.g. `Bash(${CLAUDE_SKILL_DIR}/scripts/render.sh *)` but "Workspace trust doesn't gate this field". A skill folder with `.claude-plugin/plugin.json` becomes a plugin that "can bundle agents, hooks, and MCP servers". Skills follow the Agent Skills open standard (agentskills.io). — [Claude Code skills docs](https://code.claude.com/docs/en/skills)

### Inferences
- The Read-tool downscale and the 500 KB JPEG re-encode both matter for ink line art. Fine hatching and line weight can be lost before Claude sees the image. A vision-in-the-loop step should crop panels or faces to well under 2576 px and compare at matched scale rather than passing full-resolution pages.
- An MCP tool that returns base64 images inline costs context tokens (and is capped by `MAX_MCP_OUTPUT_TOKENS`). Servers that save to disk and return a path, then let Claude `Read` the file, behave better in long iteration loops.

### Gaps
- I did not find an Anthropic page that publishes accuracy figures for Claude's visual similarity judgement (style or identity). See Q4.

### Security considerations (cited)
- Anthropic: trust each server explicitly, and be aware of prompt-injection risk from servers that fetch external content. `-p`/SDK runs auto-load project `.mcp.json` servers. — [Claude Code MCP docs](https://code.claude.com/docs/en/mcp)

- For "one reference ink drawing → consistent character panels", the shortest official path is BFL FLUX MCP (FLUX.2 multi-reference + edit attached images). ## Q3. MCP server vs project backend + CLI (via Bash) vs Claude Code skill wrapping the CLI

### Takeaway
For PoesIA, put the capability in the Python `galeria` backend (extend `ImageBackend` with reference images and a seed/model pin), expose it through the existing `poesia` CLI, and wrap that CLI in a thin Claude Code skill. Add an MCP server only if non-Claude-Code clients (claude.ai, Cursor) need it, and if so, make it a thin shim over the same backend. Anthropic's own engineering guidance favours code execution over loading many tool schemas, and the benchmark literature is mixed but has converged now that clients load tool schemas lazily.

### Cited Findings
- Anthropic engineering ("Code execution with MCP", Nov 2025): loading all tool definitions up front and passing intermediate results through the model drives up cost. Having agents write code that calls tools reduced one workflow from 150,000 to 2,000 tokens (98.7%). — [Anthropic Engineering: Code execution with MCP](https://www.anthropic.com/engineering/code-execution-with-mcp); [MarkTechPost coverage, 2025-11-08](https://www.marktechpost.com/2025/11/08/anthropic-turns-mcp-agents-into-code-first-systems-with-code-execution-with-mcp-approach/)
- Scalekit benchmark (75 runs): CLI was 10–32x cheaper and 100% reliable vs MCP's 72%. Most of the gap came from 43 tool schemas injected per conversation. Contradicted in part by Checkly (2026), which found MCP and skill+CLI token use "more or less the same" because Claude Code defers tool-schema loading. — [Scalekit](https://www.scalekit.com/blog/mcp-vs-cli-use); contradicted by [Checkly](https://www.checklyhq.com/blog/mcp-vs-cli-token-efficiency/)
- Skills load only their description until invoked and can bundle scripts executed via Bash with scoped `allowed-tools`. Plugins can bundle skills + MCP servers + hooks. — [Claude Code skills docs](https://code.claude.com/docs/en/skills)
- Replicate's own MCP offers a "code mode" (the agent writes TypeScript against the SDK in a sandbox). This shows a vendor also moving toward code over many tool calls. — [Replicate MCP docs](https://replicate.com/docs/reference/mcp)
- Community guidance (Zenn, 2026-02-28) recommends MCP when team-wide config sharing via `.mcp.json` matters, and a skill otherwise. — [Zenn guide](https://zenn.dev/long910/articles/2026-02-28-claude-gemini-nano-banana?locale=en)
- BFL ships official "prompting skills" alongside its MCP, and Google ships skills alongside mcp-genmedia. Vendors are pairing MCP (transport/auth) with skills (procedure). — [flux-mcp README](https://github.com/black-forest-labs/flux-mcp); [genmedia skills README](https://github.com/GoogleCloudPlatform/genmedia-creative-studio/blob/main/experiments/mcp-genmedia/skills/README.md)

### Inferences (applied to PoesIA)
- **Reproducibility.** A backend + CLI call can log the exact request (model ID/version, seed, reference-image hash, prompt, parameters) to a manifest in the repo. Hosted MCP gateways hide or vary these: fal and Replicate pick models dynamically, and nanobanana-mcp-server auto-selects a model from keywords. Those choices only appear in the chat transcript, not in a committed artifact.
- **Reuse in the Python app.** The `ImageBackend` Protocol is the single source of truth. An MCP server built *on* it (e.g. FastMCP wrapping `galeria`) reuses it. A third-party MCP server duplicates it and drifts from it.
- **Concrete Protocol gap.** Today's signature `generate_image(prompt, style) -> bytes` cannot carry a reference image, seed or model pin. Any of the three patterns first needs something like `generate_image(prompt, style=None, *, references: Sequence[Path|bytes] = (), seed: int | None = None, model: str | None = None)`, or a separate `ReferenceImageBackend` Protocol, so backends without reference support (Pollinations, procedural) still type-check.
- Third-party MCP servers are still useful as a **cheap exploratory probe**: try BFL/HF Kontext through MCP for a few panels before committing to implementing a backend.

### Gaps
- I found no Anthropic document that explicitly recommends "CLI + skill" over "MCP" for a project's own tools. The recommendation above is inferred from the code-execution post, the skills docs and the benchmarks.

## Q4. "Claude as art director" loops and the reliability of Claude's visual judgement

### Takeaway
The loop (Claude writes the prompt → external model generates → Claude Reads the output → critiques it against the reference → revises the prompt) is common in community skills and in vendor-shipped skills such as Google's genmedia-image-artist. I found no Anthropic-published pattern or accuracy data for it. Published evidence says MLLM judges agree with humans moderately on subject/concept preservation in the best case (GPT-4o ~0.83 Pearson on DreamBench++; Claude 3.5 lower). They are unreliable for fine-grained appearance/style differences between *good* outputs, and they are inconsistent across repeated runs. Use Claude as a coarse filter and critic, backed by an embedding metric and human sign-off, not as the final judge.

### Cited Findings
- Community skills implement the loop. One "Image Generation" skill uses Replicate MCP to generate, "automatically validates them against requirements, and refines prompts". An "Art Director" skill orchestrates style searches with feedback loops but delegates generation. smixs/visual-skills only writes prompts. (directory listings, quality unverified) — [MCP Market: Image Generation skill](https://mcpmarket.com/tools/skills/image-generation); [MCP Market: Art Director skill](https://mcpmarket.com/tools/skills/art-director-2); [smixs/visual-skills](https://github.com/smixs/visual-skills)
- Google's mcp-genmedia ships a `genmedia-image-artist` skill for "high-fidelity image generation, prompt optimization, and iterative collaborative refinement". This is a vendor example of the pattern. — [genmedia skills README](https://github.com/GoogleCloudPlatform/genmedia-creative-studio/blob/main/experiments/mcp-genmedia/skills/README.md)
- DreamBench++ (ICLR 2025) used GPT-4o as the judge for personalised generation. It reports 83.31% (concept preservation) and 98.71% (prompt following) Pearson consistency with humans, beating DINO/CLIP by +32.59 and +37.23 points. Claude-3.5 reached 74.00% on the paper's consistency-ratio measure. The dataset has 150 reference images including "stylized images". ### Inferences
- Design the loop as **pairwise, rubric-based comparison** (reference vs candidate, labelled "Image 1/Image 2", with a checklist of named character traits: hair silhouette, line weight, costume marks) rather than absolute 1–10 scores. Pairwise is the most stable judge format in the evidence above.
- Pair Claude's critique with an automatic identity/style metric (e.g. DINOv2 / CLIP embedding similarity or a character-specific embedding). Treat human approval as the gate, which also fits the Read-tool downscaling limits.
- Because Claude can't generate images, its strongest role is **prompt writing + failure triage** (wrong costume, missing feature, wrong panel composition). The evidence says these coarse failures are where VLM judges agree with humans.
